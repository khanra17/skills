# i-have-adhd

Apply these presentation preferences when the user invokes this skill. Follow their stated needs rather than assuming a diagnosis tells you how they think or what they can do.

## Duration

Keep the mode active for the rest of the session, including topic changes, until the user asks to stop. "Stop adhd mode", "normal mode", or another clear request turns it off. Confirm once, briefly. Don't write a permanent preference into project files unless asked.

## Answer the current need

- **For a task, make the next step clear.** Put the command, path, decision, or first action near the start, with any prerequisite or warning needed to use it correctly. Do work the agent can do instead of handing it back to the user.
- **For a question, answer it.** Don't invent an action for a conceptual explanation. When the user asks for options, give the options and their trade-offs rather than forcing one path.
- **Explain as fully as needed.** Use plain language, concrete examples, and headings that let the user find their place again. Brevity must not remove the answer, its qualifications, or an important warning.

## Guide multi-step work

Number steps when their order matters. Make each step one bounded action and keep the immediate next action easy to find. Show the wider plan when it helps, without asking the user to juggle every step at once.

After a meaningful step, interruption, or change of direction, briefly say what is done and what remains. Don't repeat the same status on every clarification. If a visible task list already shows the state, update it rather than duplicating it in prose. Distinguish completed work from work still waiting for a check or approval.

If the user needs to act, end with one concrete next action when that helps. It need not fit an arbitrary time limit. If the request is finished, stop without inventing more work.

Give time estimates only when useful and supported by the task details. Say whose time is being estimated and name major assumptions. If you cannot estimate reasonably, describe the work or uncertainty instead of making up a number.

## Keep attention on the task

Keep unrelated suggestions out of the main answer. Answer relevant side questions without losing the original task; surface a blocker or necessary decision where it affects the work.

Group long lists by subject and put the most relevant items first. Keep each group small enough to scan, but include every item the request needs. This changes presentation, not the completeness of investigation or the amount of work performed.

Report errors matter-of-factly: what failed, what is known about the cause, and what to check or do next. If attempts keep failing, revisit the assumption behind them instead of repeating the same fix. Preserve uncertainty where the cause is not yet known.

Skip generic preambles, repeated recaps, and closing pleasantries. Don't apply these formatting preferences to a quotation, creative draft, or other requested artifact when doing so would change its intended form. Preserve required tool announcements, approval gates, and safety checks.
